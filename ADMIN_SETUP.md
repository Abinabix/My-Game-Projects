# ABIN.EXE admin CMS setup

The CMS uses Express with PostgreSQL sessions and project data. Project screenshots are held in memory only during upload and are sent directly to Cloudinary. Configure the database and Cloudinary before uploading images.

## Local development

1. Install Node.js 20.19+ and PostgreSQL.
2. Copy `.env.example` to `.env` and set `DATABASE_URL`, `SESSION_SECRET`, `ADMIN_EMAIL`, and the Cloudinary credentials. Use a long random session secret, for example `node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"`.
3. Run `npm install`.
4. Create the first administrator with `npm run create-admin`. The password is entered interactively and is not echoed or saved in the source tree. `ADMIN_EMAIL` supplies the email; leave it unset to enter an email at the prompt.
5. Run `npm run dev:server` in one terminal and `npm run dev` in another. Vite serves the site on port 5173 and proxies `/api` to Express on port 3000.

The server applies pending SQL migrations at startup. You can also apply them explicitly with `npm run migrate`. The initial migration imports the two existing archive projects without screenshots or invented links.

## Render deployment

1. Create a Render PostgreSQL database in the same region as the web service. Copy its **internal** connection URL into the service's `DATABASE_URL` environment variable.
2. Create the Node web service from this repository using `render.yaml` (or use its build command `npm install && npm run build` and start command `npm start`). The blueprint leaves database and Cloudinary values as private environment variables to connect your own services.
3. Add `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, and the administrator email under the Render service's environment settings. `SESSION_SECRET` is generated by the blueprint; retain it between deploys so sessions remain valid.
4. Deploy. The service applies SQL migrations on startup and serves the Vite `dist` files and API together. Set or retain `NODE_ENV=production`; Render supplies `PORT`.
5. Create the first admin account from an authorized shell with the service's database URL and `ADMIN_EMAIL` configured by running `npm run create-admin`. If your service plan does not provide a shell, run the command from a trusted machine configured with the database's external connection URL, then remove that temporary URL from the machine. Never put a password in a command argument.
6. Open `/admin/login`, create a draft, upload the cover and gallery images, add project details and credits, preview, and publish.

Uploaded images are never written to the Render filesystem. If Cloudinary credentials are missing, upload requests return a configuration error; other site sections remain available when the database or API is temporarily offline.

## Migration and admin commands

- `npm run migrate` applies unapplied files from `migrations/` transactionally and records them in `schema_migrations`.
- `npm run create-admin` creates the first account only. There is no public registration endpoint.
- `npm start` launches the production Express server. The server requires `SESSION_SECRET` in production.

Keep `.env` out of version control. Do not commit database URLs, session secrets, or Cloudinary API credentials.
