# ABIN.EXE admin CMS setup

The CMS uses Express with PostgreSQL sessions and project data. Project screenshots are held in memory only during upload and are sent directly to Cloudinary. Configure the database and Cloudinary before uploading images.

## Local development

1. Install Node.js 20.19+.
2. Copy `.env.example` to `.env`. Set `DATABASE_URL` to a real PostgreSQL URL. For a Render database used from your computer, copy its complete **External Database URL** from the Render database page's **Connect** section and ensure it includes `sslmode=require` (append `?sslmode=require` if there is no query string, or `&sslmode=require` if one already exists). The external URL is different from the Render-only internal URL. Never use the `.env.example` placeholder URL as a real connection value.
3. Set a long random `SESSION_SECRET`, for example by running `node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"`, and set your `ADMIN_EMAIL`. Cloudinary variables may remain unset until you configure Cloudinary.
4. Run `npm.cmd install` in Windows PowerShell. Use `npm` on shells where the npm executable is not blocked by PowerShell's execution policy.
5. Create or recover the administrator with `npm.cmd run create-admin`. The command validates the database URL and connection, applies pending migrations, checks the schema, then prompts for the email and a hidden password. If that email already exists, type `RESET` when asked to safely update its password.
6. Run `npm.cmd run dev:server` in one terminal and `npm.cmd run dev` in another. Vite serves the site on port 5173 and proxies `/api` to Express on port 3000.

The server applies pending SQL migrations at startup. You can also apply them explicitly with `npm.cmd run migrate` in Windows PowerShell. The initial migration imports the two existing archive projects without screenshots or invented links.

## Render deployment

1. Create a Render PostgreSQL database in the same region as the web service. In the Render web service's environment settings, set `DATABASE_URL` to the database's **internal** connection URL. The internal URL is for services running on Render; use the external URL only from your computer or another external client.
2. Create the Node web service from this repository using `render.yaml` (build command `npm install --include=dev && npm run build`, start command `npm start`). The blueprint leaves database and Cloudinary values as private environment variables to connect your own services.
3. Add `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, and the administrator email under the Render service's environment settings. `SESSION_SECRET` is generated by the blueprint; retain it between deploys so sessions remain valid.
4. Deploy. The service applies SQL migrations on startup and serves the Vite `dist` files and API together. Set or retain `NODE_ENV=production`; Render supplies `PORT`.
5. Create the admin account from an authorized shell with `npm run create-admin`. If the service plan has no shell, run `npm.cmd run create-admin` from your computer using the database's external URL in the ignored local `.env`; remove that URL from `.env` when finished. Never put a password in a command argument.
6. Open `/admin/login`, create a draft, upload the cover and gallery images, add project details and credits, preview, and publish.

Uploaded images are never written to the Render filesystem. If Cloudinary credentials are missing, upload requests return a configuration error; other site sections remain available when the database or API is temporarily offline.

## Migration and admin commands

- `npm.cmd run migrate` applies unapplied files from `migrations/` transactionally and records them in `schema_migrations` in Windows PowerShell.
- `npm.cmd run create-admin` creates an account or updates its password after an explicit `RESET` confirmation. There is no public registration endpoint.
- `npm.cmd start` launches the production Express server. The server requires `SESSION_SECRET` in production.

Keep `.env` out of version control. Do not commit database URLs, session secrets, or Cloudinary API credentials.
